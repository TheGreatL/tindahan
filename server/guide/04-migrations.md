# Alembic Migrations

Alembic tracks changes between SQLAlchemy model metadata and the PostgreSQL schema.

## Configuration

Alembic was initialized with:

```powershell
cd server
uv run alembic init migrations
```

`migrations/env.py` loads the database URL and imports the SQLAlchemy metadata plus every model module:

```python
from src.database.database import Base
from src.database.models.products import ProductModel

target_metadata = Base.metadata
```

Alembic does not discover models by filename. Importing `products.py` executes `ProductModel`, which registers the `products` table in `Base.metadata`. Without importing the model module, autogeneration may see no table changes.

## Migration Workflow

Run these commands from `server`.

### Generate a migration

After creating or changing a SQLAlchemy model:

```powershell
uv run alembic revision --autogenerate -m "create products"
```

This compares model metadata with the current database schema and creates a migration in `migrations/versions/`. Always inspect the generated migration before applying it.

### Apply migrations

```powershell
uv run alembic upgrade head
```

### Check migration state

```powershell
uv run alembic current
uv run alembic history
uv run alembic check
```

`current` shows the applied revision, `history` shows the revision sequence, and `check` reports pending autogenerated operations.

### Undo the latest migration

```powershell
uv run alembic downgrade -1
```

Use `downgrade base` to revert all migrations. This can remove tables and data.
